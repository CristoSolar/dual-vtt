# i18n: English + Spanish across the whole platform

Date: 2026-09-15

## Goal

The app runs fully in English or Spanish. The user picks the language on their
device; it applies to UI text and to SRD content (classes, cards, adversaries,
weapons, …). Spanish is today's only language. English is the SRD's original
language and its JSON survives intact in git.

## Decisions already made

- **Per user, per device.** Not per campaign, not GM-defined. Data is keyed by id,
  so GM and players may read different languages at the same table at no cost.
- **Default**: `navigator.language` starting with `en` → English; anything else →
  Spanish. Stored choice wins over default.
- **No i18n library.** Plain typed dictionaries and one hook.
- **Server stays English.** Logs and `reject` messages are developer strings; the
  web renders its own text from the error *code*, never the server's `message`.

## Non-goals (explicitly accepted)

- SRD text already **stored** in state stays in the language it was created in:
  `equipment.classItem`, `inventory` strings (`BASE_INVENTORY`, `POTIONS`), and
  adversary/scene/token names the GM types or copies into the room. Fixing this
  means schema changes and a `localStorage` migration. Not now.
- No per-campaign language broadcast. No language field in protocol or server.
- No new locales beyond `en`/`es`, but nothing hardcodes the count.

## Architecture

### 1. `packages/srd-data` — two datasets, one getter

```
packages/srd-data/data/en/*.json   ← restored from commit bd82307 (13 files)
packages/srd-data/data/es/*.json   ← today's data/*.json, moved
```

Both sets have identical shape and ids (verified: same entry counts and key sets
per file).

`src/index.ts`:

- Imports all 26 JSON files. `datasets` lists every one (`name` becomes
  `en/classes.json`, …) so `validate` and the schema test cover both.
- Exports `type Locale = 'en' | 'es'` and `export const LOCALES = ['en', 'es'] as const`.
- Exports `type SrdData = { domains, classes, subclasses, ancestries, communities,
  weapons, armor, domainCards, adversaries, environments, loot, consumables,
  beastforms }` and `export const srdByLocale: Record<Locale, SrdData>`, each parsed
  once at import as today.
- Exports `setLocale(locale: Locale)`, `getLocale(): Locale`, and `srd(): SrdData`
  returning the active set. Module-level mutable state, initial `'es'`. Marked
  `// ponytail: module-level locale; thread a param through the reducers if this ever
  needs to be per-call`.
- **Removes** the bare array exports (`classes`, `adversaries`, …). Every consumer
  switches to `srd().classes` etc. Removing rather than aliasing means `typecheck`
  finds every site; nothing can silently keep reading Spanish.

`extract/README.md` gains one line: scripts write to `data/en/`; `data/es/` is a
hand-maintained translation of it.

### 2. `packages/character` — read through `srd()`

`lookup.ts` and `options.ts` replace direct array imports with `srd().x`. No
signature changes. `classItemOptions` already handles `" or "` / `" o "`.

`validate.ts` messages are already English developer strings. They stay. The web
maps `error.code` to localized text (section 4). `ValidationError.message` remains
the fallback for any code the web does not know.

### 3. `packages/protocol` — codes, not prose

`sheet.ts` effects carry five English `message` strings (`Not enough Hope (need N).`,
`No Armor Slots available.`, `Not enough gold (need N unit).`, unknown multiclass,
`Levelled up to N.`). Add a structured field next to it:

```ts
effect: { ..., message: string | null, code: SheetEffectCode | null, params?: Record<string, string | number> }
```

`SheetEffectCode = 'notEnoughHope' | 'noArmorSlots' | 'notEnoughGold' | 'unknownMulticlass' | 'levelledUp'`.
`message` stays for logs/tests; the web renders from `code` + `params`. Under
`exactOptionalPropertyTypes`, `params` is added only when present.

`RoomError` (8 codes) and gateway rejects (`badRequest`, `forbidden`, `noSeat`) are
already codes. The web dictionary gets one entry per code.

### 4. `apps/web` — dictionaries and a hook

```
apps/web/src/i18n/es.ts     ← flat object, every UI string, key → Spanish
apps/web/src/i18n/en.ts     ← same keys, typed as Record<keyof typeof es, string>
apps/web/src/i18n/index.ts  ← locale store + hook + t()
```

- Keys are dot-namespaced by component (`sheet.takeDamage`, `wizard.step1.title`,
  `error.notEnoughFear`, `validation.classRequired`). `en.ts` is typed against
  `es.ts`, so a missing key fails `typecheck`.
- Interpolation: `t('sheet.notEnoughHope', { amount: 2 })` replaces `{amount}`. One
  regex, no plural rules. Where Spanish needs a plural form, use two keys.
- Store: module-level `locale`, `subscribe`, `setLocale` → `useSyncExternalStore`.
  `setLocale` also calls `srd-data`'s `setLocale`, writes `localStorage`
  (`daggerheart-vtt:locale`, validated on read as one of `LOCALES` — anything else
  → default), and sets `document.documentElement.lang`.
- Initial locale resolved once at module load, before React renders, so the first
  paint is already in the right language and `srd()` is set before any selector runs.
- Toggle: one button in the `topbar` (`ES` / `EN`), visible on every route including
  the map overlay. Switching re-renders everything via the hook; no reload.
- All Spanish text in `.tsx` and in `state/{rollLog,auth,useCampaign,selectors}.ts`
  moves to the dictionary. Text built in non-component code (`rollLog.ts` toasts,
  `useCampaign` error toasts) calls a plain `t()` that reads the current locale, not
  the hook.
- Wizard validation errors (`StepFields.tsx`) render `t(\`validation.${code}\`)`,
  falling back to `error.message`.
- `index.html` `lang` attribute is set at runtime; the static `lang="en"` stays as
  the pre-JS value.

### 5. Data flow on switch

```
click toggle → i18n.setLocale('en')
  → srd-data.setLocale('en')          (srd() now returns English)
  → localStorage write, <html lang>
  → store notifies → useSyncExternalStore → every subscribed component re-renders
      → t() returns English UI text
      → selectors call srd() and get English SRD content
```

Nothing is sent to the server. Room state is unchanged; only rendering differs.

## Error handling

- Unknown/corrupt `localStorage` locale → default rule. Never throws.
- Unknown error code from server → generic `error.unknown` text plus the code in a
  `<code>` for debugging.
- Missing dictionary key cannot happen at runtime: keys are a TypeScript union.

## Testing

- `srd-data`: the existing schema test walks `datasets` (now 26 entries).
  Completeness assertions (9 classes, 18 subclasses, …) run against both locales.
  One new test: for every file, `en` and `es` have the same ordered list of `id`s.
- `character`: `classItemOptions` tested under both locales via `setLocale`; the
  existing Spanish assertions in `creation.test.ts` keep passing with `setLocale('es')`
  in a `beforeAll`.
- `web`: one test for the i18n store — default resolution from `navigator.language`,
  rejection of a bad stored value, `t()` interpolation, `en` and `es` key parity
  (compile-time, but a runtime assertion costs one line).
- `pnpm typecheck` is the gate for missing keys and for any leftover bare-array import.

## Migration of existing users

None needed. No stored shape changes. First load after deploy resolves locale from
the browser; Spanish-language browsers see no difference.

## Out of scope, noted for later

- Storing `classItem` as an index and `inventory` as ids so stored text follows the
  locale.
- A GM-broadcast "table language" if a real table ever wants it.
